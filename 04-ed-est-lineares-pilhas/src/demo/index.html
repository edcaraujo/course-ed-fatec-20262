Fundamentos

O Conceito de Pilha e o Princípio LIFO

A estrutura linear restrita fundamental: o último a entrar é o primeiro a sair.

🥞 Princípio LIFO (Last-In, First-Out)

Uma Pilha (Stack) é uma coleção ordenada onde todas as inserções e remoções ocorrem exclusivamente em uma extremidade chamada Topo (Top).

  • Ponto Único de Acesso: Você só enxerga e só toca no elemento do topo.
  • Base (Bottom): O primeiro item inserido fica no fundo e só sai se todos os demais forem removidos.
  • Analogias: Pilha de pratos, pilha de livros, baralho de cartas virado para baixo.
💻 Onde a Pilha é Usada em Sistemas?
  • Desfazer / Refazer (Ctrl+Z): Cada edição é empilhada; desfazer desempilha o último comando.
  • Histórico do Navegador: O botão "Voltar" desempilha a URL atual.
  • Call Stack da CPU: Grava o endereço de retorno e variáveis locais de cada chamada de função.
  • Compiladores: Checagem de sintaxe de delimitadores { } ( ) [ ] e tags HTML.
Operações & Complexidade

Operações Primitivas e Análise Assintótica

Tempo estrito O(1) em todas as manipulações no topo.

⚡ Primitivas do TAD Pilha
Operação Efeito Custo
push(x) Insere item x sobre o topo O(1)
pop() Remove e retorna o topo O(1)
peek() / top() Consulta o topo sem remover O(1)
is_empty() Verifica se tamanho == 0 O(1)
size() Retorna contagem total de itens O(1)
⚠️ Estados Críticos de Erro
Stack Underflow:
Tentativa de executar pop() ou peek() em uma pilha vazia. Dispara IndexError.
Stack Overflow:
Tentativa de executar push() em uma pilha com limite de capacidade esgotado (ou estouro de memória da CPU).

Engenharia de Software

Por que Criar Nossa Própria Classe de Pilha?

O valor da abstração, encapsulamento e proteção de invariantes de código.

🛡️ O Princípio do Encapsulamento

Em Python, listas nativas expõem métodos que violam totalmente o contrato de uma Pilha:

  • minha_lista.insert(0, x): Custa O(N) por deslocar toda a memória.
  • minha_lista[2] = 99: Acesso indexado no meio da pilha, quebrando o LIFO!
  • minha_lista.sort(): Modifica a ordem temporal dos elementos inseridos.

A classe Pilha oculta esses perigos e expõe apenas o contrato formal do TAD.

🧩 O Conceito de TAD (Tipo Abstrato de Dados)

Um TAD é um modelo matemático que especifica:

  • O QUE faz: O conjunto de operações permitidas e seus comportamentos esperados (interface pública).
  • COMO faz (oculto): A estrutura interna de armazenamento (array, nós encadeados, memória persistente).

Se trocarmos internamente uma lista por nós encadeados, nenhum código cliente é quebrado!

Implementação Autossuficiente

A Nossa Classe Pilha em Python

Apenas ~20 linhas, sem imports, pronta para ser copiada em qualquer problema.

📦 Código Puro e Autossuficiente
class Pilha:
    def __init__(self):
        self._elementos = []

    def push(self, item):
        self._elementos.append(item)  # O(1) amortizado

    def pop(self):
        if self.is_empty():
            raise IndexError("Stack Underflow: pilha vazia!")
        return self._elementos.pop()  # O(1) no final

    def peek(self):
        if self.is_empty():
            raise IndexError("Stack Underflow: pilha vazia!")
        return self._elementos[-1]    # O(1)

    def is_empty(self):
        return len(self._elementos) == 0

    def size(self):
        return len(self._elementos)
💡 Vantagens Desta Abordagem
  • Zero Imports: Não precisa importar módulos externos (como typing).
  • Portabilidade Total: Pode ser declarada diretamente no topo do seu código para envio imediato no LeetCode ou Beecrowd!
  • Didática Clara: Toda a lógica de LIFO em apenas alguns métodos intuitivos.
Arquitetura de Dados

Pilha Encadeada (Node-Based) vs Pilha em Array

Como implementar LIFO sem alocação contígua de buffers.

🔗 Implementação com Nós Encadeados
class Node:
    def __init__(self, dado, proximo=None):
        self.dado = dado
        self.proximo = proximo

class PilhaEncadeada:
    def __init__(self):
        self._topo = None
        self._tamanho = 0

    def push(self, item):
        self._topo = Node(item, proximo=self._topo)
        self._tamanho += 1

    def pop(self):
        if not self._topo:
            raise IndexError("Pilha Vazia!")
        item = self._topo.dado
        self._topo = self._topo.proximo
        self._tamanho -= 1
        return item
⚖️ Comparativo Arquitetural
Critério Pilha em Array Pilha Encadeada
Push / Pop O(1) amortizado O(1) estrito
Localidade de Cache Excelente (RAM contígua) Baixa (ponteiros dispersos)
Overhead de Memória Baixo (apenas referências) Maior (guarda nó + ponteiro)
Aplicação Prática 1

🎯 Desafio: Validação de Escopos

LeetCode #20 (Valid Parentheses) & Beecrowd #1068 (Balanço de Parênteses I)

📋 O Enunciado

Dada uma sequência de delimitadores ( ) [ ] { }, verifique se a cadeia é bem formada:

  • Todo delimitador de abertura deve ser fechado pelo mesmo tipo correspondente.
  • A ordem de fechamento deve respeitar estritamente a ordem de aninhamento.
"()[]{}" → Válido (True)
"{[]}" → Válido (True)
(] → Inválido (False)
([)] → Inválido (False)
🤔 Reflexão: Por que Contar Caracteres Falha?

Se contarmos apenas a quantidade:

Na string "([)]": temos exatamente 1 (, 1 ), 1 [, 1 ].

A contagem de cada par é idêntica! Mas a cadeia é completamente inválida porque o colchete abriu por último e deveria fechar antes do parêntese!

💡 O aninhamento é estritamente temporal: o último escopo aberto DEVE ser o primeiro a fechar. Isso é a essência do LIFO!
Algoritmo

A Mecânica da Pilha na Validação de Escopos

Como mapear aberturas e fechamentos em tempo linear O(N).

⚙️ Regras do Algoritmo
1. Encontrou Abertura

Empilhe o caractere (push(ch)). Representa uma promessa pendente de fechamento futuro.

2. Encontrou Fechamento

Se a pilha estiver vazia ou o pop() não for o par correspondente → Inválido imediato!

3. Fim da String

Se a pilha estiver vazia (is_empty()) → Válido! Se sobrou item pendente → Inválido!

Código-Fonte Autossuficiente

Solução Completa: Classe Pilha Embutida

Declarada diretamente no próprio problema para facilitar testes e submissão.

🐍 Implementação em Python
class Pilha:
    def __init__(self): self._elementos = []
    def push(self, item): self._elementos.append(item)
    def pop(self): return self._elementos.pop() if self._elementos else None
    def is_empty(self): return len(self._elementos) == 0

def validar_escopos(s: str) -> bool:
    pilha = Pilha()
    mapa = {')': '(', ']': '[', '}': '{'}

    for char in s:
        if char in mapa.values():
            pilha.push(char)
        elif char in mapa:
            if pilha.is_empty() or pilha.pop() != mapa[char]:
                return False

    return pilha.is_empty()
📊 Análise de Complexidade
  • Complexidade de Tempo: O(N)
    A string é percorrida exatamente uma vez. Cada caractere faz no máximo 1 operação de tempo O(1) (push ou pop).
  • Complexidade de Espaço Auxiliar: O(N)
    No pior caso (ex: "(((((("), armazenamos até N delimitadores na pilha.
  • Casos de Borda:
    • Fechar antes de abrir: ")("
    • String ímpar: impossível formar pares completos.
    • Aberturas sem fechamento: "(()"
Aplicação Prática 2

Notação Infixa vs Polonesa Reversa (RPN)

Como computadores e calculadoras avaliam expressões aritméticas sem ambiguidade.

📝 Notação Infixa (Humana)

O operador fica no meio dos operandos:

(3 + 4) * 5
  • Exige regras de precedência (* e / antes de + e -).
  • Exige parênteses para alterar a ordem natural.
  • Difícil para a CPU avaliar em um único passe linear.
🚀 Notação Pós-fixa / RPN (Computacional)

O operador vem após os operandos:

3 4 + 5 *
  • Zero Ambiguidade: Não precisa de parênteses!
  • Avaliação linear inequívoca da esquerda para a direita.
  • Usada nas calculadoras HP, na JVM (Java) e no interpretador Python.
Aplicação Prática 2

🎯 Desafio: LeetCode #150

Evaluate Reverse Polish Notation (Avaliação de Notação Polonesa Reversa)

📋 O Enunciado

Dado um array de strings tokens representando uma expressão em RPN, calcule seu valor numérico.

  • Operadores válidos: +, -, *, /.
  • A divisão entre dois inteiros deve sempre truncar em direção a zero.
Exemplo 1: ["2", "1", "+", "3", "*"]
((2 + 1) * 3) = 9

Exemplo 2: ["4", "13", "5", "/", "+"]
(4 + (13 / 5)) = (4 + 2) = 6
⚠️ O Ponto de Atenção Crucial

Ao encontrar um operador na pilha:

b = pilha.pop() # Segundo operando (DIREITA)
a = pilha.pop() # Primeiro operando (ESQUERDA)
resultado = a op b # a - b (NUNCA b - a!)

Na divisão inteira com números negativos em Python, usamos int(a / b) para truncar para zero!

Código-Fonte Autossuficiente

Implementação da Avaliação RPN

Código limpo em Python utilizando a classe Pilha sem imports.

🐍 Código Completo com Classe Pilha
def avaliar_rpn(tokens: list[str]) -> int:
    pilha = Pilha()
    operadores = {'+', '-', '*', '/'}

    for token in tokens:
        if token not in operadores:
            pilha.push(int(token))
        else:
            b = pilha.pop()  # operando da direita
            a = pilha.pop()  # operando da esquerda

            if token == '+': pilha.push(a + b)
            elif token == '-': pilha.push(a - b)
            elif token == '*': pilha.push(a * b)
            elif token == '/': pilha.push(int(a / b))

    return pilha.pop()
📊 Análise de Desempenho
  • Tempo de Execução: O(N)
    Cada token da lista de tamanho N realiza apenas operações em tempo constante O(1).
  • Memória Auxiliar: O(N)
    No pior caso, a pilha armazena até aproximadamente $N/2$ números antes de encontrar operadores.
  • Divisão Truncada para Zero:
    int(a / b) garante conformidade estrita com a semântica de linguagens tipadas (como C e Java).
Arquitetura de Sistemas

A Call Stack e o Limite de Recursão

Como o Sistema Operacional e o interpretador executam chamadas de função.

🧱 Anatomia de um Stack Frame

A cada chamada de função, um Quadro de Ativação é empilhado na memória Stack da CPU contendo:

  • Endereço de retorno na instrução anterior.
  • Argumentos passados por parâmetro.
  • Variáveis locais declaradas na função.

Quando a função faz return, seu quadro é desempilhado e a CPU volta ao chamador.

💥 O Perigo: RecursionError

A pilha de execução da CPU possui tamanho muito limitado para proteger a integridade do sistema operacional:

import sys
print(sys.getrecursionlimit()) # Padrão: 1000

Se uma árvore ou grafo tiver profundidade > 1000, o programa aborta com falha crítica!

Engenharia Algorítmica

Conversão de Recursão para Iteração

Substituindo a Call Stack do SO por uma Pilha Explícita na memória Heap.

🔁 Versão Recursiva (Vulnerável)
def dfs_recursivo(no, visitados=None):
    if visitados is None: visitados = []
    if not no: return visitados

    visitados.append(no.valor)
    dfs_recursivo(no.esq, visitados)
    dfs_recursivo(no.dir, visitados)

    return visitados

Estoura com mais de 1000 níveis!

🛡️ Versão Iterativa com Pilha (Blindada)
def dfs_iterativo(raiz):
    if not raiz: return []
    visitados = []
    pilha = Pilha()
    pilha.push(raiz)

    while not pilha.is_empty():
        no = pilha.pop()
        visitados.append(no.valor)

        if no.dir: pilha.push(no.dir) # Direita entra antes
        if no.esq: pilha.push(no.esq) # Esquerda entra depois (Topo!)

    return visitados

Suporta milhões de nós na memória RAM!

Python Idiomático

Simulando Pilhas com Recursos Nativos do Python

Como utilizar list e collections.deque de forma correta e veloz.

📝 Usando list Nativa

A lista nativa funciona perfeitamente como pilha se você respeitar as regras:

  • stack.append(x): O(1) amortizado (push)
  • stack.pop(): O(1) (pop no final)
  • stack[-1]: O(1) (peek)
  • not stack: O(1) (is_empty)
⚠️ NUNCA use pop(0) ou insert(0, x)! Custa O(N).
⚡ Usando collections.deque

Uma Fila de Duas Pontas (Double-Ended Queue) baseada em blocos encadeados:

from collections import deque
stack = deque()
stack.append(10)     # O(1) estrito
topo = stack.pop()   # O(1) estrito

Vantagem: Garante O(1) estrito em ambas as pontas sem realocação contígua de buffer!

Referência Avançada

🔍 Para ir além: Tipagem Estática e Genéricos

Como tipar pilhas em projetos corporativos utilizando Generic[T].

📦 Pilha com Generic[T]
from typing import Generic, TypeVar, Optional

T = TypeVar('T')

class PilhaGenerica(Generic[T]):
    def __init__(self):
        self._elementos: list[T] = []

    def push(self, item: T) -> None:
        self._elementos.append(item)

    def pop(self) -> T:
        if not self._elementos:
            raise IndexError("Stack Underflow")
        return self._elementos.pop()

    def peek(self) -> T:
        return self._elementos[-1]

    def is_empty(self) -> bool:
        return len(self._elementos) == 0
💡 Quando usar cada versão?

Em Juízes Online & Maratonas: Use a versão simples sem genéricos da aula (apenas 20 linhas e zero dependências).

Em Bibliotecas & Ambientes de Produção: Adicione Generic[T] para permitir que o mypy e a IDE validem tipos em tempo de compilação.

Revisão

Resumo dos Pontos-Chave 💡

Conceitos indispensáveis para guardar desta aula.

  • LIFO é a Lei: Inserção, remoção e consulta acontecem exclusivamente no Topo em O(1).
  • Trate Exceções: Sempre proteja contra Stack Underflow (pop em pilha vazia).
  • Validação de Escopos: O último delimitador a abrir deve ser o primeiro a fechar.
  • Notação Polonesa Reversa (RPN): Dispensa parênteses. Ao operar, b = pop() e a = pop(), calcule a op b.
  • Eliminação de Recursão: Use uma Pilha Explícita em memória Heap para evitar o limite de 1000 chamadas da CPU.
  • Em Python: list com append() e pop() é a simulação padrão em competições.
