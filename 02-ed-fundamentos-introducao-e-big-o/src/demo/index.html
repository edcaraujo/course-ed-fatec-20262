01. Motivação

Por que Analisar Algoritmos?

O problema do "tempo de relógio" (wall-clock time) e a necessidade de uma métrica universal.

⚖️ O Dilema de Maria e João

Dois desenvolvedores criaram soluções para o mesmo problema:

• Algoritmo A (Maria): 0.05 segundos

02. Análise Matemática

Contagem de Instruções e Comportamento Assintótico

Como modelar o número de passos e entender a dominância dos termos para N → ∞.

Python Contagem Passo a Passo 
def sum_list(lst):
    total = 0           # 1 instrução (atribuição)
    for value in lst:   # N iterações do laço
        total += value  # 1 instrução por iteração (N vezes)
    return total        # 1 instrução (retorno)
Total de Instruções: f(N) = N + 2
🔍 O Princípio da Dominância

Considere dois algoritmos com contagens de instruções:

  • Algoritmo 1: f(N) = 4N2 + 2N + 7
  • Algoritmo 2: g(N) = 3N2 + 5N + 13

Quando N é pequeno (ex: N = 2), as constantes e termos menores têm peso. Porém, quando N cresce para milhares ou milhões, o termo de maior expoente (N2) representa mais de 99.99% do custo total!

03. Notações Matemáticas

A Família Assintótica (O, Ω, Θ) e Casos de Análise

Limite Superior (Teto), Limite Inferior (Piso) e Limite Justo, combinados com Melhor, Médio e Pior caso.

O Big-O (Upper Bound)

Limite Superior (Teto):

"O algoritmo não demora mais do que..."

Garante um limite máximo de tempo no pior cenário possível. É a notação padrão da indústria.

Ω Big-Omega (Lower Bound)

Limite Inferior (Piso):

"O algoritmo demora pelo menos..."

Representa o mínimo de trabalho indispensável para o algoritmo resolver a tarefa.

Θ Big-Theta (Tight Bound)

Limite Justo (Exato):

"O algoritmo cresce exatamente na taxa de..."

Quando os limites superior e inferior coincidem na mesma ordem de grandeza (O = Ω).

04. Simplificação

As 4 Regras de Ouro do Big-O

Diretrizes indispensáveis para simplificar expressões algébricas de complexidade.

1️⃣ Descarte as Constantes

Multiplicações e divisões por constantes não alteram a ordem assintótica:

• O(2N) ➔ O(N)
• O(500) ➔ O(1)
• O(3N² + 100) ➔ O(N²)

Exemplo: Percorrer a lista duas vezes com dois loops sequenciais é 2N operações, ou seja, O(N).

2️⃣ Descarte Termos Não-Dominantes

Quando termos de ordens diferentes estão somados, apenas o de maior crescimento importa:

• O(N² + N) ➔ O(N²)
• O(N + log N) ➔ O(N)
• O(2N + N100) ➔ O(2N)

Exemplo: Um loop linear O(N) seguido de um loop duplo O(N2) resulta em O(N2).

3️⃣ Entradas Diferentes ➔ Variáveis Diferentes!

Se a função recebe duas listas independentes A (tamanho N) e B (tamanho M):

• Loops sequenciais: O(N + M) (Não é O(2N)!)
• Loops aninhados: O(N · M) (Não é O(N²)!)
4️⃣ Adição vs Multiplicação

Identifique a estrutura de execução do código:

• Ações Sequenciais (Passo 1 DEPOIS Passo 2) ➔ SOMA (+)
• Ações Aninhadas (Para CADA item faça...) ➔ MULTIPLICAÇÃO (·)
05. Hierarquia de Eficiência

O Zoológico das Complexidades (Big-O Zoo)

O ranking completo das ordens de grandeza, da mais eficiente à intratável.

🏆 Escala Universal de Eficiência
O(1) < O(log N) < O(N) < O(N log N) < O(N²) < O(N³) < O(2ᴺ) < O(N!)
📈 GRÁFICO INTERATIVO DE CRESCIMENTO DAS CURVAS
Observe como as curvas exponenciais O(2N) e quadráticas O(N2) sobem verticalmente enquanto O(1) e O(log N) permanecem praticamente planas.
05. Zoo: Alta Velocidade

O(1) Constante vs O(log N) Logarítmica

Acesso imediato e divisão repetida do espaço de busca.

O(1) Complexidade Constante

O tempo de execução é independente do tamanho da entrada:

def get_first(lst):
    return lst[0] if lst else None

def is_even(n):
    return n % 2 == 0

Acessar um elemento por índice em um vetor ou verificar uma chave em um dicionário (Hash Table) é O(1).

O(log N) Complexidade Logarítmica

A cada iteração, o problema é dividido pela metade:

• N = 16 ➔ 4 passos (16 ➔ 8 ➔ 4 ➔ 2 ➔ 1)
• N = 1.000.000 ➔ ~20 passos!
• N = 1.000.000.000 ➔ ~30 passos!

Exemplo clássico: Busca Binária (Binary Search) em listas ordenadas.

05. Zoo: Eficiência Prática

O(N) Linear vs O(N log N) Linearítmica

Varredura direta e a técnica ótima de Dividir para Conquistar.

O(N) Complexidade Linear

O tempo cresce na mesma proporção direta da entrada:

def find_max(numbers):
    max_val = numbers[0]
    for num in numbers:
        if num > max_val:
            max_val = num
    return max_val

Se dobrarmos os dados (N → 2N), o tempo de execução simplesmente dobra.

O(N log N) Linearítmica (Dividir e Conquistar)

O problema é dividido em log N níveis e, em cada nível, processamos todos os N elementos:

Nível 0: [------------- N -------------] ➔ N passos
Nível 1: [---- N/2 ----][---- N/2 ----] ➔ N passos
Nível 2: [- N/4 -][- N/4 -][- N/4 -]... ➔ N passos
Total de níveis: log(N) • Custo Total: N · log(N)

É o limite teórico ótimo para algoritmos de ordenação por comparação (Merge Sort, Quick Sort médio, Timsort).

05. Zoo: Laços Aninhados

O(N2) Quadrática vs O(N3) Cúbica

Laços aninhados múltiplos e a degradação rápida de desempenho.

O(N²) Complexidade Quadrática

Ocorre com frequência ao comparar todos os pares de uma lista com dois laços aninhados:

def bubble_sort(arr):
    n = len(arr)
    for i in range(n - 1):
        for j in range(n - i - 1):
            if arr[j] > arr[j + 1]:
                arr[j], arr[j+1] = arr[j+1], arr[j]
• N = 1.000 ➔ 1.000.000 operações
• N = 100.000 ➔ 10.000.000.000 operações (começa a travar o processador!)
O(N³) Complexidade Cúbica

Três laços aninhados. Exemplo: Multiplicação Tradicional de Matrizes N × N:

for i in range(n):
    for j in range(n):
        for k in range(n):
            res[i][j] += a[i][k] * b[k][j]

O espaço de operações forma um cubo tridimensional com N × N × N = N3 iterações.

Comparações: 0 Trocas (Swaps): 0 Status: Pronto para ordenar
05. Zoo: A Explosão Combinatória

O(2N) Exponencial vs O(N!) Fatorial

A barreira da intratabilidade computacional e a explosão de tempo.

O(2ᴺ) Complexidade Exponencial

A cada elemento adicional em N, o número total de operações dobra:

def fibonacci(n):
    if n <= 1:
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)
• N = 10 ➔ ~1.024 chamadas
• N = 30 ➔ ~1.000.000.000 chamadas (1 bilhão!)
• N = 50 ➔ ~1.125.899.906.842.624 chamadas (levaria anos)
O(N!) Complexidade Fatorial

Ocorre na geração de todas as permutações possíveis (ex: Caixeiro-Viajante por força bruta):

• 5! = 120 operações
• 10! = 3.628.800 operações
• 20! ≈ 2,43 × 1018 operações (mais segundos que a idade do universo!)

Torna qualquer algoritmo inviável para N > 20.

06. Trade-offs

Complexidade de Tempo vs Complexidade de Espaço

Avaliando o consumo de memória RAM auxiliar e o trade-off tempo-espaço com 3 soluções distintas.

1. Vetor de Frequência

Cria um array de tamanho igual ao maior valor (K):

• Tempo: O(N + K)
• Espaço: O(K)

⚠️ Se K = 109, alocará 1 bilhão de inteiros!

2. Conjunto Hash (Set)

Insere elementos em uma tabela hash para filtrar únicos:

• Tempo: O(N)
• Espaço: O(N)

Funciona para qualquer lista, mas consome memória linear.

3. Dois Ponteiros (Ótimo)

Aproveita que o vetor já está ordenado:

• Tempo: O(N)
• Espaço: O(1) (In-place!)

🏆 Solução perfeita: varre uma vez usando só uma variável contadora!

🧪 SIMULAÇÃO: CONTANDO ELEMENTOS DISTINTOS (DOIS PONTEIROS O(1) ESPAÇO)
Array ordenado: elementos repetidos estão lado a lado. Basta checar se arr[i] != arr[i-1]!
07. Alocação Dinâmica

Análise Amortizada: O Segredo do `list.append()`

Como operações raras e caras (O(N)) são diluídas por milhares de operações imediatas (O(1)).

💡 O que é Custo Amortizado?

Em algumas estruturas de dados, uma operação é O(1) em 99.9% dos casos, mas ocasionalmente precisa fazer um trabalho pesado de O(N) (como redimensionar um buffer).

"O custo caro ocasional é diluído e amortizado pelas muitas operações baratas consecutivas!"

Resultado: Custo médio garantido de O(1) Amortizado.

📦 A Mecânica de Redimensionamento do Python
  • 1. A lista aloca um bloco contíguo de memória com capacidade inicial C.
  • 2. Inserir elementos é O(1) enquanto houver slots livres.
  • 3. Ao encher, aloca um novo bloco com o dobro da capacidade (2C), copia todos os itens antigos (O(N)) e insere o novo.
  • 4. As próximas N inserções serão novamente O(1)!
🧪 SIMULADOR DE ALOCAÇÃO DINÂMICA (APPEND COM DUPLICAÇÃO DE CAPACIDADE)
Capacidade Inicial: 4 slots. Clique em "Inserir Elemento" para preencher!

def challenge_01(arr):

🤔 Questões para Reflexão
  • Quantas iterações o laço executa em relação a N?
  • Pular de 2 em 2 reduz a ordem de grandeza do crescimento?
  • Quanta memória auxiliar foi alocada na memória RAM?

Pela Regra 1 (Descarte de Constantes):
O(N / 2) = O(½ · N) ➔ O(N)
A memória auxiliar alocada se resume às variáveis primitivas n e i, totalizando espaço O(1).

Desafio 02: Dobrando o Índice 🎯

Qual é a complexidade de Tempo e de Espaço deste algoritmo?

Python challenge_02.py 
def challenge_02(n):
    i = 1
    while i < n:
        print(i)
        i = i * 2
🤔 Questões para Reflexão
  • Quais valores a variável i assume a cada iteração?
  • Quantas vezes podemos multiplicar 1 por 2 até ultrapassar N?
Análise Assintótica
Complexidade: Tempo: O(log N) Logarítmica • Espaço: O(1) Constante
Derivação Matemática:
A cada iteração, i assume a progressão geométrica: 1, 2, 4, 8, 16, ..., 2k.
O laço termina quando 2k ≥ n. Aplicando logaritmo na base 2:
2k = n ➔ k = log2(n) iterações
Portanto, o número total de execuções cresce na escala logarítmica O(log N).

Desafio 04: Loop Triangular (j = i + 1) 🎯

O laço interno começa em i + 1. Isso altera a classe de complexidade?

Python challenge_04.py 
def challenge_04(arr):
    n = len(arr)
    for i in range(n):
        for j in range(i + 1, n):
            print(arr[i], arr[j])
🤔 Questões para Reflexão
  • Quando i = 0, quantas vezes j roda? E quando i = 1?
  • Qual é a soma total de iterações de j?
Análise Assintótica
Complexidade: Tempo: O(N²) Quadrática • Espaço: O(1) Constante
Derivação Matemática (Soma de Gauss):
Somando as iterações do laço interno:
• i = 0 ➔ N - 1 vezes
• i = 1 ➔ N - 2 vezes
• i = N - 1 ➔ 0 vezes
Total = (N - 1) + ... + 1 + 0 = (N(N - 1)) / 2 = (N2 - N) / 2 ➔ O(N2)
Mesmo sendo metade da matriz (um triângulo), a classe de complexidade continua sendo estritamente quadrática O(N2).

def challenge_05(list_a, list_b):

🤔 Questões para Reflexão

  • A operação item in list_b é imediata ou precisa varrer a lista?
  • Como otimizar este código usando a estrutura de dados certa?

Em Python, listas são arrays lineares. A operação item in list_b faz uma busca sequencial elemento a elemento que custa O(M) a cada volta!
Tempo Total = N voltas × O(M) = O(N · M)

Se converter set_b = set(list_b) antes do loop, a busca passa a ser O(1) em média. O tempo total cai para O(N + M) linear!

Desafio 06: Concatenação Repetida de Strings 🎯

O impacto silencioso da imutabilidade de strings na memória e no tempo.

Python challenge_06.py 
def challenge_06(words):
    result = ""
    for w in words:
        result = result + w  # Concatenação
    return result
🤔 Questões para Reflexão
  • Suponha N palavras de tamanho médio K.
  • Strings em Python são mutáveis ou imutáveis?
  • O que o interpretador precisa fazer a cada operação result + w?
Análise Assintótica
Complexidade: Tempo: O(N² · K) Quadrática • Espaço: O(N · K)
Mecânica Interna:
Como strings são imutáveis, cada result + w aloca uma nova string e copia todos os caracteres anteriores:
• 1ª volta: copia K caracteres
• 2ª volta: copia 2K caracteres
• N-ésima volta: copia N · K caracteres
Total = K · (1 + 2 + ... + N) ≈ O(N² · K)
💡 Solução Ótima (Linear O(N · K)):
Utilizar "".join(words) aloca a memória apenas uma vez!
Desafio 07 / 10

Desafio 07: Recursão e a Pilha de Chamadas 🎯

Como as chamadas pendentes na Call Stack consomem memória RAM auxiliar.

Python challenge_07.py 
def countdown(n):
    if n <= 0:
        return
    print(n)
    countdown(n - 1)
🤔 Questões para Reflexão
  • A função aloca listas ou variáveis pesadas?
  • Onde ficam armazenadas as chamadas recursivas antes de atingir o caso base?
Análise Assintótica
Complexidade: Tempo: O(N) Linear • Espaço: O(N) Linear na Pilha
Comportamento da Memória:
A função é chamada N vezes até atingir o caso base (n <= 0).
Cada frame de execução permanece na pilha de chamadas (*Call Stack*):
countdown(4) ➔ countdown(3) ➔ countdown(2) ➔ countdown(1) ➔ countdown(0)
[Profundidade da pilha = N frames alocados simultaneamente]
Portanto, embora não aloque arrays, o espaço em memória é linear O(N).
Desafio 08 / 10

Desafio 08: Two Sum em Vetor Ordenado 🎯

A técnica de Dois Ponteiros (Two Pointers) para encontrar um par com soma alvo.

Python two_sum_sorted.py 
def two_sum_sorted(nums, target):
    left = 0
    right = len(nums) - 1
    while left < right:
        s = nums[left] + nums[right]
        if s == target: return (left, right)
        elif s < target: left += 1
        else: right -= 1
    return None
🤔 Questões para Reflexão
  • O vetor já está ordenado. Como os ponteiros left e right se comportam?
  • Quantos passos no máximo os dois ponteiros podem se mover juntos?
Análise Assintótica
Complexidade: Tempo: O(N) Linear • Espaço: O(1) Constante
Mecânica dos Dois Ponteiros:
• A cada iteração do laço, ou left avança (+1) ou right recua (-1).
• A distância total inicial entre os dois ponteiros é de N posições.
• Eles nunca cruzam nem voltam para trás.
Total Máximo de Iterações = N passos ➔ O(N)
🏆 Reduz um problema que seria O(N2) por força bruta para O(N) tempo e O(1) memória!

def challenge_09(arr):
    n = len(arr)
    for i in range(n):
        j = 1
        while j < n:
            print(arr[i], j)
            j = j * 2
🤔 Questões para Reflexão
  • O laço externo roda quantas vezes?
  • Para cada iteração de i, quantas vezes o laço while j < n executa?
Análise Assintótica
Complexidade: Tempo: O(N log N) Linearítmica • Espaço: O(1) Constante
Aplicação da Regra 4 (Multiplicação):
• O laço externo for i in range(n) roda exatamente N vezes.
• Para cada valor de i, o laço interno while j < n dobra j, executando log2(n) vezes.
Tempo Total = N voltas × O(log N) = O(N log N)
Não aloca memória extra além das variáveis de controle i e j (O(1)).

Desafio 10: 3 Abordagens para Detectar Duplicados 🎯

Comparando três estratégias clássicas com diferentes trade-offs de tempo e espaço.

Abordagem A (Força Bruta)
Compara todos os pares com 2 laços aninhados.
• Tempo: O(N²)
• Espaço: O(1)

Lento para N grande, mas não aloca memória extra.

Abordagem B (Ordenação)
Ordena a lista primeiro e compara itens adjacentes.
• Tempo: O(N log N)
• Espaço: O(1) ou O(N)

Excelente equilíbrio entre velocidade e consumo de memória.

Abordagem C (Hash Set)
Insere em um set e verifica se o tamanho mudou.
• Tempo: O(N)
• Espaço: O(N)

🚀 Mais rápido, mas consome memória proporcional a N.

🏆 Conclusão e Lição para a Engenharia de Software

Em desenvolvimento profissional de software, não existe "a melhor solução absoluta". Existe a solução mais adequada para as restrições do sistema:
• Se a memória RAM for extremamente restrita (ex: microcontroladores, sistemas embarcados), escolha Abordagem A ou B.
• Se o sistema precisa de baixa latência e alta vazão (ex: APIs web, microsserviços), escolha Abordagem C (Hash Set)!

10. Síntese

Resumo dos Pontos-Chave & Regras de Sobrevivência 💡

O guia definitivo para manter na mente durante toda a disciplina e carreira técnica.

1. Comportamento Assintótico
Big-O mede a taxa de crescimento com N → ∞, e não o tempo de relógio em milissegundos.
2. Simplifique Sempre
Ignore constantes e termos menores: O(3N2 + 5N + 10) → O(N2).
3. Soma vs Multiplicação
Ações sequenciais se somam (O(A + B)); laços aninhados se multiplicam (O(A · B)).
4. Cuidado com Laços Ocultos
Atenção com `in list`, `.insert(0)` e concatenação de strings dentro de loops.
5. Trade-off Tempo vs Espaço
Podemos acelerar algoritmos usando estruturas hash (O(1)) ao custo de um pouco mais de memória (O(N)).
6. A Regra dos 108 Operações
Use 108 ops/s para calcular se o seu código passará em menos de 1 segundo antes mesmo de codificar!
